# UC-20 Remove Group Member — Backend implementation plan

**Spec:** [`../specs/UC-20-remove-group-member-spec.md`](../specs/UC-20-remove-group-member-spec.md), approved 2026-10-27. **Status:** Backend implementation completed on `feature/uc20-remove-group-member`; SQL Server integration tests require an available SQL Server to execute.

## Baseline and boundaries

- Use an isolated `feature/uc20-remove-group-member` Backend worktree/branch from a reviewed clean baseline. Preserve the existing dirty Backend tree and untracked UC-21 work. Run `dotnet test TripMate.slnx` before edits and record any baseline failure.
- Inspect the chosen baseline for UC-21's `Active`/`Closed` group lifecycle and shared `InApp` migration/API. Implement missing shared foundation once, in the task below, and reuse it from both UCs; do not create duplicate columns, migrations, notification controllers, or incompatible contracts.
- Before any lifecycle backfill, audit existing `social.TravelGroups` against active `social.GroupMembers` and the Host invariant. If a row cannot safely be classified under ADR-0003, stop that migration and obtain an explicit data rule; never silently mark it `Active` or `Closed`.
- Keep Booking, payment, tickets, itinerary ownership, tour-customer groups, and Web outside this Backend change. Use explicit idempotent SQL under `database/migrations/`, not EF migrations. Apply schema before application code that maps it. Preserve existing rows and audit/backfill lifecycle data before declaring existing groups `Active`.
- Each task starts with a behavioral failing test, then minimal code, focused verification, a spec-compliance review and a code-quality review. Do not expose the removal route until membership-based read paths and navigation revocation are verified.

## Definition of done

An eligible Host can remove one Active non-Host member through the Backend API. Membership, immediate access revocation, group-only navigation termination, durable replay result, one audit row and one recipient `InApp` row commit together or roll back together. An exact retry cannot remove a later rejoined membership or duplicate side effects. The inbox is recipient-isolated and shares one contract with UC-21. Required Backend checks pass, with any environment limitation explicitly reported.
